Material models

Usermat User Reference

A reference structure for material-model scope, required input, generated state, result quantities, and verification checks.

Previous ← ACT User Reference Next End of documentation

Overview

User material models extend the constitutive behavior available to an analysis. This reference is organized so that every model can use the same sequence: applicability, inputs, internal state, outputs, and verification.

Model-specific values

Parameter names, units, admissible ranges, and defaults should be taken from the reference entry for the exact model version used in the analysis.

Model scope

Before selecting a model, confirm that its dimensional assumptions, supported element formulations, stress state, and intended material behavior match the analysis. Record the model version with the project so that the calculation remains reproducible.

Applicability checklist

  • Supported analysis type and element formulation
  • Expected unit system and parameter conventions
  • Required material calibration data
  • Known limitations and regularization requirements

Input parameters

Define all model inputs in a consistent unit system. A complete model entry should state the parameter symbol, physical meaning, unit, accepted range, and default behavior when applicable.

Validate related parameter groups together; a value can be valid in isolation while still producing an inconsistent material definition.

Output quantities

Output entries should distinguish directly computed quantities from derived values. State variables used for restart or history-dependent behavior should be documented separately from user-facing results.

  • Stress and strain measures and their coordinate system
  • Damage, plasticity, or other history indicators
  • Convergence or status flags exposed by the implementation
  • Energy quantities used for verification

Verification

Verify a material definition on a small, controlled model before using it in a full structure. Compare the response with an analytical result, a published benchmark, or an independently implemented calculation.

  1. Check the initial elastic response and unit consistency.
  2. Exercise each expected loading branch and unloading path.
  3. Review state variables and energy balance across load steps.
  4. Repeat the check with a refined increment or mesh where relevant.
